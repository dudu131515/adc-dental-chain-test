预约开始和结束采用 Asia/Shanghai。前一个工作日按原预约门店核准的工作日历回溯，应用按诊所 ID 读取已核准版本。预约主项目用于预计占时和资源匹配，其他预计诊疗意向仍可作为意向记录。专用椅位停用由具备本店权限的主管录入。查询统计以服务器收到本次报告请求的时刻为截止。

## 合成验收样例

| 用例 | 关键场景 | 预期 |
|---|---|---|
| UC01 | 同一牙医从 A 店结束到 B 店开始相差 59 分钟或 60 分钟 | 59 分钟拒绝，60 分钟仍需核对资质与转场可行性 |
| UC02 | 10:00–11:00 预约，唯一适配椅 10:30–11:00 维修 | 整段不可约，其他可行时段仍可查询 |
| UC02 | 工作日历指定周一前一工作日为周五 | 周五 20:00 整可自办或代办，之后患者原因改期拒绝；诊所原因另协商 |
| UC02 | 10:00–10:30 预约改到 10:15–10:45 | 无其他冲突时原子替换，有冲突则原约及预约金保留 |
| UC02 | 10:00–10:30 预约，尝试提前确认爽约，或已签到、诊所延误 | 保留签到及其他事实。10:30 起由前台核实未到、未取消且店内可接诊，才记录爽约 |
| UC03 | 到店后原椅临时停用，另有专用椅预约 | 在本店适配且可用的余量中分椅，保留其他有效预约的可行分配；无法履约按诊所原因处理 |
| UC04 | 主单应收 120 元，已经成功收款 60 元，批准整单冲销 | 原 Invoice 与原始明细保留，差额 -120 元，退款办理 60 元，在途时净实收仍为 60 元，退款成功后为 0 |
| UC04 | 同单分两笔成功支付后退款 | 每笔退款关联其原收款并走原渠道，该原收款的累计在途与成功退款不超过原实收 |
| UC06 | 8 笔到期有效应履约预约，4 笔实际接诊、1 笔患者取消、1 笔爽约、2 笔未处置 | 共享分母为 8，接诊率 50%、患者取消率 12.5%，未处置单列；诊所取消及尚未结束预约不入分母 |
| UC07 | 原季度第 1 版净利润 270 元，后续同季度获批减少应计 120 元，成本不变 | 原净利润 270 元、基金 27 元保留，第 2 版确认后显示净利润 150 元、基金 15 元及基金差额 -12 元 |
| UC01–07 | 两家虚构门店、一名跨店牙医、患者和各员工角色合成账号 | 邀请真机体验或通过开发工具验收全链，并执行跨店和个人资料越权反例 |

## 数据库实测

已通过隔离 PostgreSQL 17.11 验证。实际目录为 40 张表、268 个字段、70 条外键、4 个视图。验证覆盖停用区间、椅型快照字段、重叠改期与回滚、爽约操作者、查询截止、主单冲销、退款原收款引用及原季度版本。验证样例全部回滚。

在空白隔离测试库使用 psql 的 ON_ERROR_STOP 模式，依次执行设计脚本和验证脚本。末尾预期看到 PASS ADC PostgreSQL schema and scenario tests。
