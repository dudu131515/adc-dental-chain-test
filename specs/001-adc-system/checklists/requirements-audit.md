- [ ] CHK006 「到期未处置」是否有能够唯一解释的预约状态定义？［清晰，Spec FR-602、FR-603、AC-06-01、AC-06-02，母本 §5.7、已确认设计 SQL 的统计口径］
  - **不通过**。FR-602 列出该分组，但未说明截至查询截止仍处「已确认」或「已签到」的已结束正式预约如何分类，可能漏算已签到未接诊。**建议** 按同源 SQL 已写明的口径补足两种状态，明确与爽约、患者取消、实际接诊互斥，给两种状态分别补充例子。
- [ ] CHK007 患者原因改期与诊所原因协商改期的截止适用范围是否清楚区分？［缺口，Spec FR-206、FR-207、AC-02-05、AC-02-06，母本 UC02 5a、表 5-5］

- [ ] CHK008 患者普通取消的可用状态和关闭时点是否均已被批准？［歧义，Spec FR-208、FR-209、§状态与联动，母本表 3-2、图 4-12］
  - **待确认**。FR-208 定义金额档位，但以「可取消」作为前置条件。母本有「合法取消」「已签到但未实际接诊按已确认责任办理」，患者自办在预约开始后尚未接诊时的截止与渠道仍未写明。**建议** 请作者确认哪些预约状态和时点允许自办或授权代办，再与爽约核实及已签到人工处理衔接。既有金额档位保持原样。

## 3 业务流程完整性

- [ ] CHK009 发布供给到经营核算是否在统一记录上定义主体、前置及交接结果？［完整性，Spec §系统边界与业务主链、FR-004、AC-X-02，母本表 B-1］
  - **通过**。排班和项目提供预约供给，预约关联唯一就诊和原款，实际项目传入主单，季度读取经营事实，全链以同一组业务对象衔接。
- [ ] CHK010 跨店排班、整段椅池和到诊分椅的主要条件及回退是否明确？［流程，Spec FR-101–104、FR-201–203、FR-301、FR-302，I01、I02、I07］
  - **通过**。有牙医确认及再发布、拒绝回拟、适配椅整段、排除停用、到诊才分具体椅、保持其余占位可行及故障优先同店协调。资格期间细节见 CHK003。
- [ ] CHK011 诊疗、计费、价格和季度版本是否规定了主要交接及不变条件？［流程，Spec FR-304–308、FR-401–408、FR-501–503、FR-705–707］
  - **通过**。签到与实际接诊独立、追加先同意、拒绝留痕、完成及中止交接、历史快照、唯一主单与差额、季度原版和已确认修订均明确。
- [ ] CHK012 占位尚未到期但成功回执到达时已无法履约，是否有明确的资金与资源处理结果？［缺口，Spec FR-203–205、FR-210、AC-02-04，母本 UC02 4／4a、I03］
  - **不通过**。FR-204 要求占位有效且资源合法才确认。FR-205 直接定义的是占位已失效或释放后的晚到成功。付款已成功、占位尚未转正且未到期、但牙医停诊或椅池重查失败的组合没有明确终态。**建议** 保留已付款事实和不得确认不可履约预约的现行规则，由作者核准该分支的释放与资金处理。候选是复用唯一原路退款义务，另写拒绝建单、原款及重放结果的验收。该候选尚未获批。

## 4 角色权限完整性

- [ ] CHK013 角色表是否覆盖母本的全部角色、入口和基本对象范围？［完整性，母本表 3-1、表 5-4，Spec FR-001、FR-002、§角色、入口与授权范围］
  - **通过**。7/7 个角色有对应。本人与门店、本次诊疗职责及总部功能和范围均体现在统一网站和小程序。
- [ ] CHK014 「履职必要」「最小临床数据」是否能直接落成可核对的字段及交接边界？［缺口，Spec FR-002、FR-003、FR-303、FR-308、AC-X-01、SC-006，章程 IV、母本表 5-4］
  - **不通过**。当前能判断原则性越权，仍不能从 Spec 决定前台在签到和结算各可看哪些字段、牙医因当前预约取得哪些历史资料、总部明细见患者的何种投影。**建议** 以岗位动作和对象关系补最小可见字段矩阵，列出有权查看当前事实和无权查看临床明细的成对场景，由作者审核字段、适用时段及授权范围。继续沿用母本的最小权限原则。
- [ ] CHK015 诊所原因跨店改期及数据交接是否已明确授权主体和新旧门店可见范围？［歧义，Spec FR-002、FR-004、FR-104、FR-206、FR-207，母本 UC01 5a、UC02 5a、表 3-1］
  - **待确认**。母本指定患者同意和本店权限。Spec 写明门店可变，但跨店时原店发起、目标店承接、总部协调各能做什么及事后可查的历史范围仍未明确。技术方案拟核对两店范围，实际谁可代哪一方办理仍需业务授权依据。**建议** 作者确认受影响动作和交接可见字段，再补单店员工、双店授权、总部协调及患者同意的正反例。
- [ ] CHK016 查询、核算、复核和确认是否有可区分的权限要求？［一致性，Spec FR-001、FR-002、FR-705、AC-X-01、SC-006，母本表 5-4］
  - **通过**。总部经营权限按动作写明，查询授权不会自动成为确认授权，原始来源及审计受相同访问范围约束。

## 5 异常处理完整性

- [ ] CHK017 已确认的抢占、过期、改期失败、同意拒绝及终止是否保持可见的原业务事实？［异常覆盖，Spec FR-203–206、FR-302、FR-304–308、AC-02-03–05、AC-03-01–04］
  - **通过**。资源竞争不会形成超量预约，已知重复或晚回执的处理结果、失败改期保留原号原款、签到保留、追加拒绝和中止的主要恢复均可追溯。
- [ ] CHK018 已签到未接诊、诊所延误或争议完成核实后，是否能从需求判定动作与结果？［缺口，Spec FR-207–210、AC-02-07，母本表 3-2、图 4-12］
  - **不通过**。已规定保留签到和禁止误判爽约。「按确认的责任办理」未给出核实后按哪一条现有流程办理、哪些情况下预约保持有效，以及如何反馈退金。**建议** 对照母本文字增加责任确认前的保留状态，以及责任确定后的现有取消或协商分支及验收证据。未批准的归责与资金口径先确认。
- [ ] CHK019 诊疗退款失败、重试和回执晚到是否具有一致、可追溯的结果定义？［缺口，Spec FR-404、FR-405、FR-408、AC-04-03–05，母本 UC04 4a／4b、§5.6］
  - **不通过**。成功与在途的净实收口径清楚，失败时的授权补办、是否继续关联同一原付款及同一义务、迟到或重复结果的状态优先级未形成明确验收。FR-210 的重试明文针对预约金。**建议** 对诊疗资金补充失败结果可见性、当前净实收不变、同一退款和原支付的追溯，以及可执行的重试与重复结果场景。任何不同于原规则的资金处理先审批。
- [ ] CHK020 对结果未知的提交，是否定义了如何确认实际状态、恢复原过程和防止重复处理？［恢复，Spec FR-008、FR-205、FR-404、FR-407、AC-X-04、SC-007，已审核 UI/UX §两端交接和异常反馈］
  - **不通过**。UI/UX 已写连接中断时先查实际结果、保留输入。Spec 的 AC-X-04 与 SC-007 只列五类反馈，未纳入「动作可能已提交但未收到结果」。**建议** 引入已审核的恢复行为，为预约变更、收付或确认用例写清结果未知、已有成功和可重试的判定，复用现有去重要求。

## 6 验收标准可测试性

- [ ] CHK021 关键数值和业务结果是否有具体可判定的验收样例？［可测试性，Spec SC-002–005、AC-02-04、AC-02-06、AC-02-07、AC-04-04、AC-06-01、AC-07-03］
  - **通过**。占位截止、退金边界、当场核实、原收款冲销、同分母及已确认版本均有可观测结果，例如 8 笔样例 4/8 和 1/8、公司基金 27／15／-12 元。
- [ ] CHK022 场景的给定、行为和结果能否对每个被声称覆盖的分支独立成立？［可测试性，Spec FR-102、FR-103、FR-206、FR-401、AC-01-02、AC-02-05、AC-04-01］
  - **不通过**。AC-01-02 的给定全为不合格情形，预期却包含合格满 60 分钟可发布。AC-02-05 的给定已有日历，预期还声称覆盖缺日历。AC-04-01 给定为已结束且证据齐全，预期还判断未结束和缺证据。**建议** 将这些分支拆成前置互斥的场景或具名数据行，保留原通过及拒绝规则。
- [ ] CHK023 递增修订、顺序复核和重复来源是否都能被现有季度场景检验？［可测试性，Spec FR-706、FR-707、AC-07-03、SC-005，Q03-2］
  - **不通过**。AC-07-03 只有一个差额来源和一个修订版，能核对重复来源，却不能判定两个不同差额如何递增、在前版待复核时能否确认后版，以及每版包含哪些累计差额。**建议** 按 FR-706 增加同季度两条不同已批准入账差额以及尝试先确认后版的分支。预期精确认定最新可见版、各差额来源及版本取数。
- [ ] CHK024 经营报告的主要数量和资金指标是否有针对各自来源的可核算预期？［可测试性，Spec FR-604、AC-06-03、SC-004，母本表 1-2、UC06 3］
  - **不通过**。AC-06-03 预期只明确治疗种类的区分、标准覆盖可核对及可见范围，未列出应计、实收、退款和欠款在同一期间中分别应为多少，标准覆盖也缺少可判定的样例数。**建议** 从既批准的实际项目和成功流水口径构造小数据，给出各类结果的精确预期。若报表时间基准存在两个合理解释，先确认后再定该预期。

## 7 业务规则一致性

- [ ] CHK025 预约金、患者取消、人工爽约及预约项目时长是否与已确认决策一致？［一致性，Spec FR-201、FR-203、FR-208–210，母本表 3-2、表 5-3，Q01、Q02-1］

- [ ] CHK026 实际接诊、计费、原始单据和净实收分别采用一致的业务来源吗？［一致性，Spec FR-304–307、FR-401–408，I06、I08–I11，Q03-1］
