# ADC 微信原生小程序

患者端使用微信原生框架，与管理端共用同一套 Django API 和 PostgreSQL 业务数据。页面不保存本地业务真相；预约、改约、取消、预约金与诊疗账单均通过后端接口读写。

## 页面与入口

- 首页：品牌、下一次就诊、预约入口、历史预约、预约金、诊疗费用、门店、本人资料。
- 预约：门店 → 项目（含参考价与标准时长）→ 日期 → 牙医与可约时段 → 确认 → 模拟预约金。
- 我的预约：待就诊、历史预约、详情、改约、取消、预约金退款状态。
- 费用：诊疗费用单（全部/待缴/已结清）、账单明细、计费项目、收退与退款记录；预约金记录单独可查。
- 我的：本人资料、待就诊/费用单/待缴金额概览、历史记录、门店地址与电话。

## 本地开发

1. 启动后端（项目根目录）：
   ```powershell
   python backend/manage.py runserver 127.0.0.1:8000
   ```
2. 在 `services/environment.js` 中保持：
   ```js
   const LOCAL_API_BASE = "http://127.0.0.1:8000/api/v1";
   const LOCAL_SYNTHETIC_LOGIN_CODE = "<本地合成登录码>";
   ```
   本地合成登录码与服务端 `ADC_MINI_SYNTHETIC_CODES` 配置一致，仅开发版和回环地址生效。
3. 微信开发者工具导入 `mini-program/`，在「详情 → 本地设置」勾选“不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”，使用开发版调试。
4. 运行服务层逻辑测试：
   ```powershell
   node --test mini-program/tests/*.test.cjs
   ```

## 体验版与正式发布

- `project.config.json` 中的 AppID 为项目已有配置，不要替换为未核实的 AppID。
- 体验版/正式版必须使用已备案并配置 HTTPS 证书的后端域名，在 `services/environment.js` 设置：
  ```js
  const EXPERIENCE_API_BASE = "https://<已核实的后端域名>/api/v1";
  ```
  并在微信公众平台「开发管理 → 开发设置 → 服务器域名」把该域名加入 request 合法域名。
- 当前仓库没有已核实的公网 HTTPS 后端域名，网站 ICP 备案仍在办理中；因此体验版/正式版尚不能作为已配置成功的环境对外声明。完成备案、部署 HTTPS 后端并在微信后台配置合法域名后，才能进行真机体验版验收。
- 课程演示使用微信开发者工具的本地开发版和模拟预约金；不接入真实微信支付。

## 与管理端联动

患者预约后，管理端前台在预约日历可看到同一预约；改约、取消、签到、接诊、开单和模拟收款都写回同一后端。患者端「诊疗费用单」读取管理端开立的主单及收退记录，不使用本地假数据。
