# ADC GitHub Pages 演示

[打开公开演示](https://dudu131515.github.io/adc-demo/) · [静态发布仓库](https://github.com/dudu131515/adc-demo)

正式模式和演示模式从 `web/src/main.tsx` 启动，使用同一个 StaffApp、AppShell、权限导航和业务页面。正式端调用 Django API。演示端使用内存模拟 API、合成数据和顶部的样例身份选择。页面刷新后恢复初始业务数据，切换身份时保留当前的业务变更。

| 一级入口 | 左栏子入口 | 用例与需求 |
| --- | --- | --- |
| 首页 | 授权门店及经营概况 | FR-010 |
| 门诊运营 | 今日门诊、预约日历、跨店排班、排班需求、牙椅停用 | UC01、UC02、FR-010 |
| 患者与诊疗 | 患者档案、接诊队列、诊疗记录 | UC03、FR-212、AC-03-05 |
| 收费与日结 | 结算队列、账单与收退、日结对账、更正与审批 | UC04、FR-409、FR-410 |
| 经营与配置 | 经营总览、门店对比、经营智能助手、费用管理、绩效管理、项目与价格、门店资料、员工与权限、牙医资质、资质类型、牙椅管理、耗材管理 | UC05 至 UC07、FR-011、FR-606、FR-607 |

## 业务连贯演示

1. 选「前台」，进入「门诊运营 → 预约日历」，选林明远的候选空档，搜索样例患者「赵青」，选口腔检查。完成模拟预约金，打开预约详情，确认签到并分配可用牙椅。
2. 切换到「牙医」（林明远），在接诊队列打开该患者，核对过敏史，开始接诊，保存一项治疗并正常结束。
3. 切回中心门诊前台，用新预约号搜索结算队列。开立主单并模拟收款，可在患者档案和日结对账查到这笔办理。
4. 切换「总部管理人员」，在经营总览查看营业收入、诊疗成本、经营费用、净利润、预约履约、牙医工作量与诊椅利用趋势；点击指标可回查同次查询的明细。门店对比可选两个期间比较收入、成本、利润与资源效率，绩效管理保留季度试算、复核、确认与历史版本。
5. 跨店排班用总部身份拟排、牙医身份答复、总部身份发布。总部管理人员同一账号可访问排班、项目价格、经营总览和绩效管理。系统管理员在顶部「更多身份」中，进入「员工与权限」可分别维护岗位资料和门店授权。

6. 在周排班里用「批量拟排」保存多行，也可在班次详情选目标日期复制。「复用上一周」会跳过重复班次。选中草案批量提交，切到相应牙医回应，再切回总部批量发布。周表同时显示缺口、转场风险和待处理班次。
7. 用系统管理员增改门店和员工资料，单独配置账号与权限。用总部配置身份维护牙医资质、牙椅、可预约的项目、价格版本及耗材成本版本。切换到获授权的业务身份后，可在排班、预约或诊疗看到对应资料。

## 构建

在根目录运行 `npm --prefix web run dev:demo` 启动演示。运行 `npm --prefix web run build:demo` 输出 `web/demo/dist`。相对资源路径和 hash 路由兼容项目级 Pages 子路径。静态站点禁用外部连接，付款、退款及助手分析均为本地模拟。部署仓库从 main 分支根目录提供产物。
