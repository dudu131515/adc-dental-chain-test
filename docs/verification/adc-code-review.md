# ADC 代码审查报告

审查日期 2026-11-24。独立审查覆盖预约、排班、身份与诊疗，结算、支付、统计与部署，以及 React 和微信原生客户端。当前项目目录没有 Git 历史，因此以当前源码、现行规约、API 契约、已审核界面和联验记录为依据。受限数据库角色和异常资金恢复中的关键问题均用本机合成资料验证。

## 问题及复核

| 严重程度 | 源码位置 | 原因及业务影响 | 修复及证据 |
|---|---|---|---|
| P1 阻断部署 | [数据库授权脚本](../../backend/scripts/grant_db_access.py#L16) | 应用角色对员工、门店和牙椅只有 SELECT。普通运行账号不能取得行锁，核心排班、占位、分椅等事务失败。 | 三张表仅授权主键列 UPDATE 以支持加锁，同时拒绝具有全库数据权限的角色。回归验证字段更新边界，完整业务链在受限角色下通过。[PostgreSQL 17 权限说明](https://www.postgresql.org/docs/17/ddl-priv.html#DDL-PRIV-UPDATE) |
| P1 跨店隐私 | [排班 API](../../backend/adc/scheduling/api.py#L124) | 班次和预约看板以牙医本人标识放行时遗漏同店授权，撤销原店权限后仍可能显示该店患者姓名，并允许回应相关班次。 | 看板、班次、回应及患者姓名投影只使用当前 DENTIST 门店范围。回归覆盖同一牙医曾获该店权限后被撤销。 |
| P1 代办付款 | [预约金模型](../../backend/adc/booking/models.py#L39) | 数据库将新预约金记为 PENDING，客户端把该值理解成已发起。前台首次付款和释放按钮无法显示。 | 占位回执和原付款查询统一用 NOT_STARTED 区分尚未发起与已在途。覆盖前台发起、放弃、迟到回执与原路退款。 |
| P1 资金结果恢复 | [退款 API](../../backend/adc/billing/refund_api.py#L47) · [网站收退面板](../../web/src/features/billing/InvoiceFunds.tsx#L71) | 新退款没有按原动作查询，异常响应和离开主单后可能丢失原动作，重复收退会影响余额。 | 收款和退款按账号与主单保留原动作。再次进入先读取权威结果，原动作查无结果时才按原键提交。覆盖无有效响应、重新打开及同键回查。 |
| P1 微信资金回查 | [小程序恢复服务](../../mini-program/services/deposit-recovery.js#L5) · [预约金记录](../../mini-program/pages/receipts/index.js#L6) | 预约金记录原先只由正式预约生成。放弃或到期后的迟到成功可能有退款而无正式预约，退出页面后患者找不到原款。 | 同设备按 API 环境及账号保留待核对原操作。回查仍由服务端授权，可查迟到退款，隔离其他账号。覆盖无效响应、读取失败、重新进入和原键恢复。 |
| P2 并发改期 | [改期服务](../../backend/adc/booking/reschedule_service.py#L47) | 同一动作并发进入时，后进入的请求可能在幂等结果查询前误判旧占位已变。 | 加锁后先确认原动作结果及当前权限。相同动作回读，同键异载荷或新键旧占位仍分别拒绝。检查只记录一次改期。 |
| P2 审批与入账 | [结算更正 API](../../backend/adc/billing/correction_api.py#L62) · [更正页面](../../web/src/features/billing/CorrectionReview.tsx#L61) | 审批可改变原申请差额，前台却只看到建议值。金额或符号不一致时，可能按误读的审批金额办理。 | 入账与显示采用同一审批凭据。覆盖申请金额与批准金额不同的情形。 |
| P2 履职权限和投影 | [诊疗投影](../../backend/adc/clinical/visit_api.py#L80) · [诊疗页面](../../web/src/features/clinical/VisitDetail.tsx#L40) · [结算开单](../../web/src/features/billing/BillingPage.tsx#L13) · [流水读取](../../backend/adc/billing/invoice_api.py#L99) | 进行中就诊漏返回本次过敏核对。混合角色直达详情时可能出现不可操作的治疗或开单入口。关联更正的本店主管原来也无法回查流水。 | 分别按责任牙医投影、实际开单权和本店关联更正权限展示并执行。测试覆盖过敏历史、双角色、同店无关联、跨店与写权限。 |
| P2 报表口径 | [财务事实查询](../../backend/adc/reporting/fact_queries.py#L39) | 报表在同一查询截止下混用实时主单余额和截至该时点的资金流水，截止边界附近应计、欠款可能提前包含后续回执。 | 同一数据库快照内按截止筛选主单、差额和成功收退，再逐单核欠款。覆盖回执截止前、恰好发生及后续差额。 |
| P2 恢复范围 | [补跑工具](../../backend/adc/payments/management/commands/replay_simulated_funds.py#L19) | 恢复手册要求逐笔核对，补跑命令原来只能整批扫描。因此已确认可补跑的义务和待核实义务不能分别处理。 | 恢复命令可按多组资金类型与原 ID 筛选。重复执行沿用原义务，未列入以及已暂停的记录保持原状态。 |
| P2 查询与页面衔接 | [占位查询](../../backend/adc/booking/hold_service.py#L197) · [小程序预约入口](../../mini-program/pages/booking/index.js#L6) | 改期占位没有独立预约金，误进占位回查可触发服务端错误。从门店页预约时也可能回到默认店。 | 占位查询只接受有原预约金的记录。小程序按已选门店筛选时段。测试覆盖 404 与两店选择。 |
| P1 临床更正隐私 | [更正字段投影](../../backend/adc/billing/correction_api.py#L46) | 同一人保留原店前台角色、撤销原店牙医角色后，其他门店的牙医权仍可能使前台看到自己早先记录的临床更正原因和摘要。 | 临床字段同时校验本店牙医权和实际就诊责任。已有前台的必要金额投影继续可读。测试覆盖混合角色撤权后的字段隔离。 |
| P2 网站代办恢复 | [代办表单](../../web/src/features/schedule/BookingForm.tsx#L26) | 关闭或刷新表单后，原占位、付款和退金上下文丢失。 | 同标签页按账号和门店保留原动作。打开后查原占位及最新付款，无原提交时按原键重试。特殊需求及估时依据需要重新输入并校验原文，本地存储仅保留标识和摘要。覆盖重新打开、账号隔离、在途放弃及原键重试。 |
