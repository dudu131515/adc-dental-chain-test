# ADC 连锁牙医诊所产品体验与界面设计

2026-11-22 · 设计稿 · 基线 001-adc-system

ADC 有两个入口。**一个管理网站**用于员工办理排班、预约、诊疗、结算、项目标准与经营工作。**一个微信小程序**用于患者本人预约、查看、改期、取消及查询预约金结果。网站使用同一登录入口、导航框架和详情布局，按账号权限显示对应功能和数据。两端围绕同一预约记录衔接，随后关联就诊、主单与经营事实。[统一需求规约](../../../specs/001-adc-system/spec.md) · [项目章程](../../../.specify/memory/constitution.md)

网站采用**按业务组织导航，以日程和队列承载日常操作，以关联详情完成交接**的方案。排班适合时间网格，接诊和收退适合顺序处理，经营核对适合数据表。统一详情保留相关记录编号，让使用者从当前场景继续办理。定向对比过以单笔预约详情作为主入口和以汇总看板作为主入口，前者适合复核个案，后者适合周期分析。本方案把两者放在预约日程和经营页内可直接到达的位置。

## 管理网站

### 全站导航与页面结构

| 一级导航 | 页面与操作 | 覆盖 |
| --- | --- | --- |
| 排班与预约 | 预约日历、预约列表与详情、代办预约、改期／取消、人工爽约核实、签到与分椅。按权限进入排班需求、跨店排班、本人班次确认和本店牙椅停用记录 | UC01、UC02、UC03 1／1a |
| 诊疗 | 接诊队列、患者履职所需病史与过敏、实际接诊、实做项目与耗材、追加同意、结束／中止。已开单更正从同一次就诊发起并关联原主单 | UC03、UC04 4b |
| 结算 | 待结算队列、原始主单、应计与实收收退、待审批更正和获批差额办理。打开记录直接进入该主单及允许的相关操作 | UC04 |
| 项目与价格 | 项目目录、项目表单、价格版本及生效区间。筛选或详情中可核对项目单位、资格、预计时长与适配椅型 | UC05 |
| 经营 | 经营报告、费用登记、季度核算和版本对照。按已授予的查询、登记、核算、复核或确认权限显示操作 | UC06、UC07 |

- 顶栏左侧显示 ADC 和页面路径，右侧显示当前门店范围与账号。有跨店权限时，门店范围可切换，单店账号直接显示所属店。经营报告的筛选栏明确显示实际查询范围。
- 左侧统一导航按授权显示。登录进入第一个可办理的业务页，有预约访问权时优先打开当天日程。排班、临床、结算与经营页面共用同一布局规则。
- 列表和日程点击记录打开右侧详情，轻操作在详情内完成。诊疗记录、主单和季度复核使用独立详情页，回到列表保留门店、日期和筛选。
- 同一范围内的预约详情首行显示预约号、门店、医生、项目、起止时间和履约状态。签到、牙椅及预约金分行显示，有权访问时才展示就诊和结算链接。审批、下钻和直接打开详情链接均遵循原有权限，前台临床资料保持最小可见范围。

### 关键页面

**预约日历和签到。** 页面顶部为日期、门店、医生和状态筛选，以及有权限时可用的「代办预约」。默认今日，医生为列、时间为行，切换到列表可看跨时段预约和待办事项。卡片显示时间、患者识别信息、主要项目和履约状态。详情呈现当前可办理动作。当预约已签到、椅位未确定时，清楚显示「已签到 · 待分椅」，避免误认为已经接诊。打开「分配牙椅」显示本店可选椅位，提交后再次核对整体预约的可行分配。失败时保留签到，并说明同店替代或诊所原因协调路径。

**跨店排班。** 周视图按牙医排列，同一牙医的门店与班次状态直接出现在时间块。详情并列呈现前后班次、两店间隔、资格有效性、路线核对和牙医回应。确认前可修改草案，发布前显示冲突及满足条件的下一步。停诊或椅位故障时提供受影响预约列表，从原记录办理同店替代、协商改期或诊所原因取消。

**诊疗详情。** 顶部固定显示预约号、患者、责任牙医、门店和分配的椅位。正文按「病史与过敏」「本次治疗」「耗材」分区。接诊前核对的过敏信息与风险说明仅向有权牙医显示。点击「开始接诊」后显示实际开始时间及预约金退款办理状态。对追加项目，先记录患者同意或拒绝，再记录实际实施。正常结束和中止分别展示，缺少实际项目时不能正常结束。中止确认须填写原因，页面反馈牙椅释放和待结算状态。

**结算详情。** 顶部固定主单号及当前结算状态。先展示应计、净实收、欠款或应退余额，再展示原始收费明细和实际收退流水。预约金另在关联信息中显示。获批调整显示原额、差额、调整后应计、审批和办理结果，主单号与原始明细可回查。办理诊疗退款时，先选同一主单下的成功原收款，逐笔展示原收金额、已退／在途金额和本次可退限额。主单状态和资金在途状态分别显示。零额中止显示「已结清 · 无需付款」。

**项目与价格。** 目录优先展示项目、单位、资格、预计占时、椅型与当前价。详情并列已生效和后续价格版本，新增版本时可见冲突区间。保存成功的反馈说明生效起止，既有预约按原时段和椅型展示，已有诊疗和结算按各自原始快照核对。

**经营报告与季度核算。** 报告顶端固定展示期间、门店、牙医及本次查询截止。预约指标显示原值和分子／分母，例如「实际就诊率 50% · 4/8」「患者主动取消率 12.5% · 1/8」。同屏单列爽约 1、到期未处置 2 和诊所原因取消。用状态分布条显示共享分母，用表格比较门店及回查预约事实。治疗量、资格、标准覆盖与资金使用各自的口径说明，零分母显示「不适用」，缺数据显示「缺少数据」。季度页先显示正式确认版本，再展示可复核的应计、耗材、直接费用、共同费用、实际分钟、分摊和未分配金额。修订对照按「原版／差额／最新已确认」呈现，待复核版本带文字说明且不进入正式报告。

## 患者微信小程序

底部保留「预约就诊」「我的预约」两个入口。本人资料在「我的预约」右上角维护，也可在预约确认前更新必要信息。预约成功和改期后返回同一预约详情。该详情首屏显示门店全称及地址、日期、起止时间、医生、首要项目和预约号。

| 页面 | 页面从上到下 | 主操作及反馈 |
| --- | --- | --- |
| 预约入口 | 当前门店与可切换门店 → 主预约项目 → 所选日期 | 「查看可约时段」。无默认占时的复杂项目提示由牙医估时、前台办理 |
| 医生与时段 | 门店、项目摘要 → 日期条 → 医生及其可约时段 → 所选时段 | 「确认所选时段」。无合适资源时保留门店与项目，可换日期或时段 |
| 确认与预约金 | 诊所地址和时段 → 本人信息 → 预约金 50 元、取消和改期规则 → 付款办理 | 取得临时占位后显示 10 分钟倒计时和「模拟支付 ¥50.00」。付款结果待核验时显示实际进度，回执核验成功后展示正式预约号 |
| 预约成功及详情 | 预约状态 → 地点、就诊时段和预约号 → 改期截止 → 预约金状态 | 「查看我的预约」或在允许时「改期」。取消置于次操作，显示退金金额或留存后再确认 |
| 改期、取消与退款 | 原预约与拟选新安排，或原时段、取消原因及本次退金 → 办理结果 | 改期页面保留原安排，成功后显示新时段、原号与原款，失败返回原预约。取消提交前显示按当前时点计算的退款，受理后显示退款实际状态 |
| 我的预约与本人资料 | 接下来要做的预约 → 历史预约 → 本人资料入口 | 查看有权访问的本人预约和资金结果。空列表直接提供「去预约」 |

交互沿门店、项目、医生与时间逐步收窄候选。复杂项目需要门店协助，过期、失败或支付晚到时提供查结果或重选时段的入口。小程序预约金流程使用课程模拟资金。诊疗结算由网站处理，患者从前台提供的结算凭据核对诊疗收费。

## 两端交接和异常反馈

| 时点 | 界面反馈与恢复动作 | 规约依据 |
| --- | --- | --- |
| 时段刚被占用／不存在合格资源 | 显示「该时段已不可预约」及可选时段，保留已选门店、项目和日期。付款前呈现最新资源结果 | FR-201 至 FR-203、AC-02-02／03 |
| 占位 10 分钟到期，模拟支付晚到 | 显示「占位已到期，预约未确认」。确认晚到付款并登记退金后显示「全额原路退款处理中」，收到成功结果后才显示「已退」 | FR-203 至 FR-205、FR-210、AC-02-04 |
| 改期截止、日历缺失或新资源竞争失败 | 显示原门店按本地工作日历计算的实际截止，如「最晚周五 20:00，可于 20:00 整提交」。失败时显示原因和仍有效的原预约。诊所原因改期需确认患者同意 | FR-206、FR-207、AC-02-05 |
| 取消可能产生部分退款或留存 | 确认框先显示本次应退金额、原付款方式和预约失效后果。点击后按提交时点复核，金额变化时要求查看最新结果再确认。诊所原因全额原路退 | FR-208、FR-210、AC-02-06 |
| 预约已逾时 | 门店列表可显示「待核实」。仅原规约条件成立且本店授权前台核实后显示「爽约」，登记原因；已签到、有争议或诊所延误解释相应处理状态 | FR-209、AC-02-07 |
| 签到但无椅／已接诊但退金失败 | 前者保持「已签到」并显示分椅失败及替代动作；后者保持「就诊中」并单独显示预约金退款失败与授权重试 | FR-301 至 FR-304、FR-210、AC-03-01／02 |
| 已结束、中止或结算更正 | 进入同一次就诊的唯一主单。区分原始收费、获批差额、欠款、在途及成功退款，并保留每笔原收款关联 | FR-307、FR-308、FR-401 至 FR-408、AC-03-04、AC-04-01 至 AC-04-05 |
| 季度证据不足或修订待确认 | 显示缺项及可补齐的位置。版本对照显示当前正式版本和待复核版本的身份，业务报表采用最近一次正式确认版本 | FR-605、FR-705 至 FR-707、AC-07-02／03 |
| 无权限、首次加载或连接中断 | 无权限时给出通用反馈并回到可访问页面。读请求可重试。可能已提交的操作提示先核对实际结果，提交中保留输入并阻止重复操作。结果反馈以该笔记录的真实状态为准 | FR-002、FR-003、FR-008、AC-X-01、AC-X-03／04 |
| 已到预约开始或已签到且未接诊 | 普通取消入口提示由门店核实。门店界面按继续接诊或核实后的取消结果办理，核实前保留原状态和资金进度 | FR-208、FR-209、AC-02-12、AC-02-13 |
| 付款成功但资源已不可履约 | 反馈「预约未确认」，显示原路全额退金进度，继续从原付款查询。重复回执不会出现第二个预约号或退款义务 | FR-205、FR-210、AC-02-14 |
| 跨店交接与原路退款失败 | 目标店显示当前预约，原店只展示本店交接及资金证据。诊疗退款失败的授权重试保留同一退款义务，已在途先核对，冲突暂停办理 | FR-002、FR-206、FR-207、FR-408、AC-02-15、AC-04-07 |

预约、诊疗、收款、退金和审批有各自的状态。列表上的「待分椅」「待核实」用于指示下一步动作，业务状态仍按规约记录。网站从预约进入相关就诊和主单时保留关联编号，经营下钻保留查询范围。小程序始终展示患者本人预约的最新可见安排。

## 视觉系统

现代医疗科技风格以浅灰蓝工作背景、白色内容区域和医疗蓝主操作为基础。日历、队列和表格强调扫描速度，患者页面强调清晰的就诊信息和适合单手操作的控件。面板使用边框区分，预约详情与确认弹层保留必要层次。

| 设计项 | 拟定值与使用方式 |
| --- | --- |
| 背景与正文 | 背景 `#F5F8FC`，内容区 `#FFFFFF`，正文 `#17283E`，次级文字 `#4C6179`，分区线 `#D7E1EB` |
| 操作与关键状态 | 主操作 `#1763C4` 配白字。成功用青绿 `#086E63` 配浅青底 `#E5F5F1`，待处理用琥珀 `#8A4B12` 配浅暖底 `#FFF4DF`，失败及高风险确认用红 `#A61B35` 配浅红底 `#FDEDF0`。状态同时用文字表达 |
| 字体与数字 | 中文优先设备系统字体，英数可用 Inter 并跟随系统回退。桌面主题标题 24、正文 14–16、表格辅助 13 像素。金额、指标和时间使用等宽数字，表格金额右对齐 |
| 结构与间距 | 采用 4、8、12、16、24、32 的间距。桌面左栏约 220 像素，常用详情侧栏约 400–460 像素。小程序内容边距约 16，主要触控区至少 44 像素，底部操作避开系统安全区 |
| 响应式与交互 | 窄屏时左栏收起，日历可回到预约列表，详情满宽展示。键盘可访问筛选、日历事件、表格和弹层。显示键盘焦点、表单错误及预约结果，关闭弹层回到触发控件 |
| 元件 | 日期栏、筛选条、日历事件、队列行、状态标签、详情侧栏、金额明细、确认弹层和版本对照统一样式。预约时间用当地日期及起止时间，资金有人民币标识及分位精度 |

| UC03 | 签到分椅、接诊队列和诊疗详情。参与者能分辨签到、实际接诊和结束，能理解停用换椅、追加被拒绝及中止的结果 |
| UC04 | 待结算、主单、更正审批与逐笔退款。参与者能核对主单号、历史收费、差额、小计和实际资金 |
| UC05 | 项目目录和价格版本。复查同项目时间冲突、项目估时和调价后的原有快照 |
| UC06 | 经营报告、筛选与明细。确认 4/8、1/8、截止时间和到期未处置的含义，试阅空分母与无权限结果 |
| UC07 | 本店费用登记、季度复核、修订版对照。确认未分配费用、待补、待复核和正式版本可辨认 |

设计走查采用两家虚构门店、一名跨店牙医和一条贯通的预约记录。顺序为项目与班次发布、手机预约、网站签到分椅与治疗、前台结算、总部经营查询和季度核算。另复查失败改期保留原约、已签到不得误判爽约、退款在途以及季度原版仍有效。视觉评审确认任一页面能辨认当前门店、业务状态、主要操作及失败后下一步。依据 AC-X-01 至 AC-X-04。

## 方案阶段输入

- 网站首页落点、日历视图、详情侧栏、小程序两项导航与上文色板为本次产品设计决定。原规约中的权限、金额、业务状态和统计规则作为设计输入。
- 设计以合成数据制作界面。正式的页面原型审阅按网站预约日历、诊疗详情、结算原收款、经营与季度对照，以及微信小程序选时／确认／预约详情贯通。R01 确认本期包含即时反馈和查询，主动提前提醒归后续范围。

## 工作台与患者连续服务补充

- 网站登录进入统一工作台。门店与工作日期切换控制 KPI、分时图、履约状态和预约日程。总部分发入口依据当前账号的业务授权。深色导航和低饱和医疗青色用于所有员工工作区。
- 前台通过患者名册查询和登记，患者档案含必要身份、联系和本店预约时间线。由档案进入预约详情或预选患者办理新预约。
- 责任牙医在接诊准备与进行中诊疗中看到过敏三态和当前条目，提交后记录人员、时间和变更。历史按访问关系呈现。
- 小程序导航为首页、预约、我的。首页优先呈现下次就诊和预约入口。预约按待就诊、历史归类，个人中心提供门店、资金记录和本人资料。
