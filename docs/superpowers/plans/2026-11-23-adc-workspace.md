# ADC 工作台与患者服务完善计划

目标是让门店人员进入系统即能接手工作，患者能从同一个微信小程序找到下一次就诊。现有七条业务线继续共用同一套 PostgreSQL 事实记录、Django 权限校验与资金服务。依据为 specs/001-adc-system/spec.md 和 docs/superpowers/specs/2026-11-22-adc-product-ui-design.md。

|任务|实施范围与接口|交付及验收|
|---|---|---|
|T064 门店工作台|web/src/shared、features/dashboard、main.tsx，读取现有受权预约列表|首页按门店与业务日期展示当日队列、状态分布与可用入口；切换范围、日期及角色，检查统计与预约详情一致。无预约权限的总部人员仍可进入已授权的业务。|
|T065 患者档案|backend/adc/booking/patient_api.py、web/src/features/patients、预约登记及代办表单|受权前台按姓名、编号、手机号查找患者，分页查看同店预约、登记新患者并直接代办。测试其他店、患者空档、跨店历史、返回路径及隐私字段。|
|T066 过敏核对|backend/adc/clinical、web/src/features/clinical|负责牙医在签到后、实际接诊前后均可核对。区分未核实、已确认无已知过敏及已知过敏。测试并发旧版本、无履职权限、既有风险和历史核对。|
|T067 患者小程序|mini-program 原生页面、服务、导航和样式|从首页查看自己的下一次预约、进入预约、记录和本人档案。覆盖正在就诊、预约金核对、空状态、断线重试、结算边界。运行原生模板编译和患者端测试。|
|T068 可复验的本地体验|项目的演示数据、验收证据及需求文档|用独立合成资料跨端核对同一预约和门店；构建网站，运行后端、前端与原生小程序测试并检查实际呈现。同步最终提交版项目母本、Spec、UI 和 API。|

全程以真实接口驱动。工作台涉及患者信息时使用角色最小投影，临床编辑记录核对责任人和时间。小程序模拟预约金、取消退金沿用系统已有规则。
